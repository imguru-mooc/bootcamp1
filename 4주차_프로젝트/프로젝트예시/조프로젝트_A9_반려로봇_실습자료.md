## 1. 프로젝트 개요

### 1.1 시나리오

로봇 거치 폰이 사용자의 표정(happy/sad/neutral)과 제스처(손 흔들기 =
호출, 손바닥 = 쓰다듬기)를 인식합니다. 로봇은 입력에 따라 다가오기·
물러나기·주변 맴돌기·몸 흔들기(wiggle) 같은 **행동**으로 반응하며, RGB
LED 색과 LCD 이모지 얼굴로 감정 상태를 표현합니다. 우선순위가 높은
입력(호출)은 진행 중인 행동을 중단시킬 수 있습니다.

기능 나열이 아니라 **"반려동물 같은 생동감"이 목표**인, 행동 설계
중심의 주제입니다.

### 1.2 학습 목표

1. 행동(behavior)을 데이터(시퀀스+LED+LCD)로 정의하고 실행기를 분리하는 설계를 할 수 있다.
2. 입력 우선순위와 행동 중단 가능성(interruptible)을 설계할 수 있다 — 행동 트리의 초급 개념.
3. 표정 분류와 제스처 인식 두 파이프라인을 한 페이지에서 운용할 수 있다.
4. "성격 파라미터"(반응 속도·행동 크기)를 조정하며 인터랙션 품질을 평가할 수 있다.

### 1.3 시스템 구조

```
〔로봇 거치 폰〕 인식 웹앱 (한 페이지)
   ├ Face Landmarker blendshapes → /emotion (happy/sad/neutral, 엣지)
   ├ Hand: 손바닥 펴기 유지     → /palm (Bool, 엣지)
   └ Hand: 좌우 흔들기          → /call (Bool, 엣지)
        │
       wss ──── rosbridge_server ───▶ 〔관찰자 폰〕 상태 뷰(선택)
        │
        ▼
〔Pi〕 behavior_node (우선순위 중재 + 행동 실행기)
        ├─ /cmd_vel (10Hz 연속) ──▶ 터틀봇
        ├─ /led_color (엣지) ──▶ RGB LED
        └─ /lcd_text (엣지) ──▶ LCD 이모지 얼굴
```

## 4. 구현 가이드

### 4.1 🧠 표정 분류 (blendshape 규칙 기반)

Face Landmarker의 blendshapes에서 규칙으로 분류합니다(모델 학습 불필요).

```javascript
const s = Object.fromEntries(result.faceBlendshapes[0].categories
  .map(c => [c.categoryName, c.score]));
let emotion = 'neutral';
if ((s.mouthSmileLeft + s.mouthSmileRight) / 2 > 0.5) emotion = 'happy';
else if (s.browInnerUp > 0.5 && (s.mouthFrownLeft + s.mouthFrownRight) / 2 > 0.3)
  emotion = 'sad';
publishOnChange(emotion);   // 8프레임 디바운스 + 변화 시만
```

임계값은 조원 3명 이상으로 실험해 조정하세요(인식률 표가 산출물).

### 4.2 🧠 제스처 2종

- **손바닥(palm)**: 손가락 5개 펴짐이 1초 유지 → 1회 발행 (Week 2 손가락
  개수 판정 로직 재사용).
- **흔들기(call)**: 손목(landmark 0)의 x좌표가 1.5초 내 좌우 방향 전환
  3회 이상 → 1회 발행.

두 제스처가 동시에 잡히는 상황(흔드는 손바닥)의 분리 기준을 정해
INTERFACE.md에 명시하세요 — AI B의 대표 설계 결정입니다.

### 4.3 🤖 behavior_node.py (py_compile 검증 완료)

```python
#!/usr/bin/env python3
"""behavior_node: 표정·제스처·호출 우선순위 기반 반려로봇 행동"""
import time
import rclpy
from rclpy.node import Node
from std_msgs.msg import String, Bool
from geometry_msgs.msg import Twist

# 행동 정의: 이름 → (동작 시퀀스[(lx,az,초)], LED 색, LCD 이모지)
BEHAVIORS = {
    'come':    ([(0.10, 0.0, 2.0)],                 'green',  '(^o^)/'),
    'retreat': ([(-0.08, 0.0, 1.5)],                'blue',   '(T_T)'),
    'circle':  ([(0.05, 0.8, 4.0)],                 'purple', '(o_o)?'),
    'wiggle':  ([(0.0, 1.0, 0.5), (0.0, -1.0, 0.5)] * 2, 'orange', '(>_<)'),
    'idle':    ([],                                  'white',  '(-_-)zzz'),
}
# 우선순위: 호출 > 쓰다듬기 > 표정
EMOTION_MAP = {'happy': 'come', 'sad': 'retreat', 'neutral': 'circle'}


class BehaviorNode(Node):
    def __init__(self):
        super().__init__('behavior_node')
        self.sub_emotion = self.create_subscription(String, '/emotion', self.on_emotion, 10)
        self.sub_palm = self.create_subscription(Bool, '/palm', self.on_palm, 10)
        self.sub_call = self.create_subscription(Bool, '/call', self.on_call, 10)
        self.pub_vel = self.create_publisher(Twist, '/cmd_vel', 10)
        self.pub_led = self.create_publisher(String, '/led_color', 10)
        self.pub_lcd = self.create_publisher(String, '/lcd_text', 10)
        self.route = []
        self.current = 'idle'
        self.busy_until = 0.0
        self.timer = self.create_timer(0.1, self.tick)
        self.start('idle')
        self.get_logger().info('behavior_node 시작')

    def start(self, name):
        """행동 시작: 동작 시퀀스 적재 + LED·LCD 엣지 발행"""
        seq, color, emoji = BEHAVIORS[name]
        self.current = name
        self.route = [list(s) for s in seq]
        self.busy_until = time.time() + sum(s[2] for s in seq)
        led = String(); led.data = color; self.pub_led.publish(led)
        lcd = String(); lcd.data = emoji; self.pub_lcd.publish(lcd)

    def interruptible(self, priority):
        """우선순위 높은 입력은 진행 중 행동을 중단 가능"""
        rank = {'call': 3, 'palm': 2, 'emotion': 1}
        cur_rank = {'come': 1, 'retreat': 1, 'circle': 1,
                    'wiggle': 2, 'idle': 0}.get(self.current, 0)
        return rank[priority] > cur_rank or time.time() > self.busy_until

    def on_call(self, msg):
        if msg.data and self.interruptible('call'):
            self.start('come')

    def on_palm(self, msg):
        if msg.data and self.interruptible('palm'):
            self.start('wiggle')

    def on_emotion(self, msg):
        if self.interruptible('emotion'):
            self.start(EMOTION_MAP.get(msg.data, 'idle'))

    def tick(self):
        cmd = Twist()
        if self.route:
            lx, az, remain = self.route[0]
            cmd.linear.x, cmd.angular.z = float(lx), float(az)
            self.route[0][2] = remain - 0.1
            if self.route[0][2] <= 0:
                self.route.pop(0)
                if not self.route:
                    self.start('idle')
        self.pub_vel.publish(cmd)      # 10Hz 연속


def main():
    rclpy.init()
    node = BehaviorNode()
    try:
        rclpy.spin(node)
    except KeyboardInterrupt:
        pass
    finally:
        node.destroy_node()
        rclpy.shutdown()


if __name__ == '__main__':
    main()
```

> ⚠️ **스타터 코드의 알려진 한계(조가 해결할 것)**
> ① 행동이 끝나면 무조건 idle로 돌아가 **감정의 여운이 없습니다**
> (happy였다는 사실이 사라짐) — S2·C1의 "기분 상태" 설계로 개선하세요.
> ② `interruptible`에서 emotion(1) vs come(1)처럼 동급이면 행동 완료까지
> 대기하는데, 이 정책이 옳은지(예: sad로 급변하면 즉시 반응해야 하나?)
> 조가 토론해 결정하고 근거를 남기세요. ③ idle의 LCD가 '(-_-)zzz'로
> 즉시 덮여 직전 감정 이모지가 사라집니다 — 연출 관점에서 개선 여지.
