## 1. 프로젝트 개요

### 1.1 시나리오

사용자는 **화면을 전혀 보지 않습니다.** 음성으로 목적지("출입구",
"창가")를 말하면 로봇이 앞장서 주행하고, 사용자는 로봇의 소리를 따라
걷습니다. 전방 장애물은 초음파로 감지해 **부저 간격**(가까울수록
빠르게 — 후방 카메라 주차 센서 방식)으로 알려주고, 상태 변화(출발·
정지·도착)는 TTS 음성으로 안내합니다.

이 주제의 제약 조건이자 본질: **모든 피드백은 소리로만.** 화면에 아무리
좋은 UI를 만들어도 점수가 아닙니다. 소리만으로 "지금 무슨 상황인지"를
전달하는 비시각 인터페이스 설계 역량을 요구합니다.

### 1.2 학습 목표

1. 비시각(청각 중심) 인터페이스를 설계하고 눈 가림 테스트로 검증할 수 있다.
2. 연속 센서값(거리)을 시간 간격 신호(부저 주기)로 변환하는 매핑을 설계할 수 있다.
3. 음성 인식(STT)과 음성 안내(TTS)의 왕복 대화 흐름을 구현할 수 있다.
4. 안내 주행에서 사용자 보행 속도와의 협조(속도·정지 정책)를 설계할 수 있다.

### 1.3 시스템 구조

```
〔사용자 목걸이/손잡이 거치 폰〕 음성 인터페이스 웹앱 (화면 사용 금지)
   ├ Web Speech STT: 목적지 발화 → /voice_dest (엣지)
   └ TTS: /tts_text 수신 → 음성 안내 재생
        │
       wss ──── rosbridge_server
        │
        ▼
〔Pi〕 guide_node ──/cmd_vel(20Hz 연속)──▶ 터틀봇 (선도 주행)
   ▲ /obstacle_dist (연속 10Hz)   └─/buzzer_tick(가변 간격 엣지)──▶ 부저
   └ 초음파 노드 (전방)
```

### 1.4 조원 역할 (5~6인)

| 역할 | 담당 | 핵심 산출물 |
|---|---|---|
| 🌐 웹 | STT+TTS 음성 인터페이스 (무화면 운용) | voice.html |
| 🤖 ROS A | guide_node (경로+부저 간격 매핑) | 노드 + 매핑 설계 문서 |
| 🔩 HW A | 초음파 노드, 부저(소리 크기·높이 튜닝) | 노드 + 소리 설계 |
| 🎧 UX | 비시각 인터페이스 설계 + 눈 가림 테스트 총괄 | 소리 어휘집 + 테스트 결과 |
| 🤖 ROS B | 경로 실측, 보행 협조 속도 정책 | 경로표 + 정책 문서 |

## 3. 토픽 인터페이스 정의서 (INTERFACE.md 초안)

| 토픽명 | 메시지 타입 | 발행자 | 구독자 | 주기 | 성격 | QoS |
|---|---|---|---|---|---|---|
| /voice_dest | std_msgs/msg/String (목적지) | 음성 웹앱 | guide_node | 발화 인식 시 | 엣지 | RELIABLE |
| /obstacle_dist | std_msgs/msg/Float32 (m) | 초음파 노드 | guide_node | 10Hz | **연속** | RELIABLE |
| /buzzer_tick | std_msgs/msg/Bool | guide_node | buzzer_node | 가변 간격 | 엣지(가변) | RELIABLE |
| /tts_text | std_msgs/msg/String | guide_node | 음성 웹앱 | 이벤트 시 | 엣지 | RELIABLE |
| /cmd_vel | geometry_msgs/msg/Twist | guide_node | 터틀봇 | 20Hz | **연속** | RELIABLE |

> ⚠️ `/buzzer_tick`은 "간격 자체가 정보"인 특수한 엣지 토픽입니다.
> 연속 스트림(`/obstacle_dist`)을 받아 **시간 간격으로 재부호화**하는
> guide_node의 매핑 함수가 이 시스템의 심장입니다. 매핑이 선형이어야
> 하는지(사람 귀는 비선형), 최소·최대 간격은 얼마여야 구분되는지 —
> 눈 가림 테스트로 답하세요.

### 4.1 🌐 음성 인터페이스 (voice.html)

A6의 STT 패턴 재사용(ko-KR, continuous, onend 재시작). TTS는 A12 패턴
(사용자 제스처 1회 활성화 — 시각장애 사용자 가정이므로 **큰 전체 화면
터치 영역**으로).

```javascript
rec.onresult = (e) => {
  const text = e.results[e.results.length - 1][0].transcript.trim();
  for (const dest of ['출입구', '창가'])
    if (text.includes(dest))
      destTopic.publish(new ROSLIB.Message({ data: dest }));
};
```

### 4.2 🤖 guide_node.py (py_compile 검증 완료)

```python
#!/usr/bin/env python3
"""guide_node: 음성 목적지 → 선도 주행 + 거리 비례 부저 간격 (비시각 피드백)"""
import time
import rclpy
from rclpy.node import Node
from std_msgs.msg import String, Bool, Float32
from geometry_msgs.msg import Twist

# 목적지별 경로 시퀀스 (실측 보정)
ROUTES = {
    '출입구': [(0.08, 0.0, 5.0)],
    '창가':   [(0.08, 0.0, 3.0), (0.0, 0.5, 3.1), (0.08, 0.0, 3.0)],
}
OBSTACLE_STOP_M = 0.25    # 이내면 정지
BEEP_MAX_M = 1.0          # 이 거리부터 부저 시작
GUIDE_SPEED_NEAR = 0.05   # 사용자와 협조: 천천히


def beep_interval(d):
    """거리 → 부저 간격: 1.0m=1.2초 ... 0.25m=0.15초 (가까울수록 빠르게)"""
    d = max(OBSTACLE_STOP_M, min(BEEP_MAX_M, d))
    ratio = (d - OBSTACLE_STOP_M) / (BEEP_MAX_M - OBSTACLE_STOP_M)
    return 0.15 + ratio * 1.05


class GuideNode(Node):
    def __init__(self):
        super().__init__('guide_node')
        self.sub_dest = self.create_subscription(String, '/voice_dest', self.on_dest, 10)
        self.sub_dist = self.create_subscription(Float32, '/obstacle_dist', self.on_dist, 10)
        self.pub_vel = self.create_publisher(Twist, '/cmd_vel', 10)
        self.pub_buzzer = self.create_publisher(Bool, '/buzzer_tick', 10)
        self.pub_tts = self.create_publisher(String, '/tts_text', 10)
        self.route = []
        self.dist = 999.0
        self.last_beep = 0.0
        self.timer = self.create_timer(0.05, self.tick)   # 20Hz (부저 정밀)
        self.get_logger().info('guide_node 시작')

    def say(self, text):
        msg = String()
        msg.data = text
        self.pub_tts.publish(msg)         # 엣지: 음성 안내

    def on_dest(self, msg):
        dest = msg.data.strip()
        if dest in ROUTES:
            self.route = [list(s) for s in ROUTES[dest]]
            self.say(f'{dest}까지 안내를 시작합니다. 부저 소리를 따라오세요.')
        else:
            self.say('모르는 목적지입니다. 다시 말씀해 주세요.')

    def on_dist(self, msg):
        self.dist = float(msg.data)

    def tick(self):
        now = time.time()
        cmd = Twist()
        if self.route:
            if self.dist < OBSTACLE_STOP_M:
                pass                       # 장애물: 정지 (경로 유지, 해소 시 재개)
            else:
                lx, az, remain = self.route[0]
                cmd.linear.x, cmd.angular.z = float(lx), float(az)
                self.route[0][2] = remain - 0.05
                if self.route[0][2] <= 0:
                    self.route.pop(0)
                    if not self.route:
                        self.say('목적지에 도착했습니다.')
            # 거리 비례 부저 (연속 스트림 → 간격 제어)
            if self.dist < BEEP_MAX_M and now - self.last_beep > beep_interval(self.dist):
                self.last_beep = now
                buz = Bool(); buz.data = True
                self.pub_buzzer.publish(buz)
        self.pub_vel.publish(cmd)          # 20Hz 연속


def main():
    rclpy.init()
    node = GuideNode()
    try:
        rclpy.spin(node)
    except KeyboardInterrupt:
        pass
    finally:
        node.destroy_node()
        rclpy.shutdown()


if __name__ == '__main__':
    main()
```

> ⚠️ **스타터 코드의 알려진 한계(조가 해결할 것)**
> ① 장애물로 정지했다가 해소되면 **말없이 재출발**합니다 — 사용자
> 입장에서 로봇이 갑자기 사라지는 경험입니다. 정지/재개 TTS 안내를
> 추가하세요(M4의 실제 요구). ② 사용자가 뒤처져도 로봇은 계속 갑니다 —
> S2 보행 협조가 이 주제의 대표 설계 과제입니다(후방 감지 수단이
> 없다면 "N초마다 잠깐 멈춰 확인 멘트" 같은 시간 규칙도 유효한 설계).
> ③ 부저 간격 매핑이 선형인데, 사람은 짧은 간격 차이에 둔감합니다 —
> 눈 가림 테스트에서 "50cm와 30cm를 구분할 수 있는가"를 검증하고
> 매핑을 개선하세요(S1).
