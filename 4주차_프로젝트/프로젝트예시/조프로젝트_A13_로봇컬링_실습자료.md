## 1. 프로젝트 개요

### 1.1 시나리오

바닥에 표적(하우스)을 그리고, 선수는 제한 시간 안에 폰으로 로봇을
조종해 표적 중심에 최대한 가깝게 세웁니다. **이 프로젝트의 본질은 경기가
아니라 심판 자동화입니다.** 천장(또는 높은 삼각대) 거치 폰이 로봇 위의
색상 마커를 검출해 위치를 실시간 추적하고, 샷 종료 시 표적과의 거리로
점수를 자동 판정합니다. 대진표·점수판 대시보드와 경기 타이머(부저)까지
갖춘 하나의 대회 운영 플랫폼을 만듭니다.

### 1.2 학습 목표

1. 색상 기반 마커 검출로 평면 좌표 측정 시스템을 구축할 수 있다.
2. 픽셀 좌표 → 정규화 좌표 변환과 측정 오차(조명·왜곡)를 다룰 수 있다.
3. 측정(연속 스트림)과 판정(엣지 이벤트)을 분리한 심판 구조를 설계할 수 있다.
4. 대회 운영 데이터(대진·점수·기록)를 상태로 관리하는 웹앱을 만들 수 있다.

### 1.3 시스템 구조

```
〔천장/삼각대 거치 폰〕 마커 검출 웹앱 ──/robot_pos(연속 5Hz)──┐
〔선수 폰〕 조종 웹앱(가상 조이스틱) ──/joy_cmd(연속)──┐        │
                                                      ▼        ▼
  wss ──── rosbridge_server ──▶ 〔Pi〕 drive_node → /cmd_vel   score_judge
                                                                │ /shot_score(엣지)
〔운영 PC/폰〕 대회 대시보드 (대진표·타이머·점수판) ◀────────────┘
        └─ /end_shot(엣지, 심판 선언) / /match_timer → buzzer_node
```

### 1.4 조원 역할 (5~6인)

| 역할 | 담당 | 핵심 산출물 |
|---|---|---|
| 🧠 AI | 색상 마커 검출 + 좌표 정규화 | tracker.html + 정확도 실험표 |
| 🤖 ROS A | score_judge (판정) | 판정 노드 + 링 규격서 |

## 4. 구현 가이드

### 4.1 🧠 색상 마커 검출 (tracker.html)

로봇 상판에 형광색(예: 분홍) 원형 마커를 부착합니다. 캔버스에 프레임을
그린 뒤 픽셀 순회로 해당 색 범위의 무게중심을 구합니다.

```javascript
function findMarker(ctx, w, h) {
  const img = ctx.getImageData(0, 0, w, h).data;
  let sx = 0, sy = 0, n = 0;
  for (let y = 0; y < h; y += 4) {          // 4px 건너뛰기 (성능)
    for (let x = 0; x < w; x += 4) {
      const i = (y * w + x) * 4;
      const [r, g, b] = [img[i], img[i+1], img[i+2]];
      if (r > 180 && b > 120 && g < 120) {   // 분홍 범위 (현장 조명에 맞게 보정)
        sx += x; sy += y; n++;
      }
    }
  }
  return n > 30 ? { x: sx / n / w, y: sy / n / h } : null;   // 정규화
}
setInterval(() => {
  const p = findMarker(ctx, W, H);
  if (p) posTopic.publish(new ROSLIB.Message({ data: JSON.stringify(p) }));
}, 200);   // 5Hz 연속
```

💡 색 임계는 현장 조명에서 반드시 재보정하세요. 검출 픽셀을 화면에
오버레이하면 튜닝이 몇 배 빨라집니다.

### 4.2 🤖 score_judge.py (py_compile 검증 완료)

```python
#!/usr/bin/env python3
"""score_judge: 천장 카메라 좌표 → 표적 거리 → 점수 자동 판정"""
import json, math
import rclpy
from rclpy.node import Node
from std_msgs.msg import String

TARGET = (0.5, 0.5)          # 표적 중심 (정규화 좌표)
# 점수 링: 반경(정규화) → 점수
RINGS = [(0.06, 5), (0.12, 3), (0.20, 1)]


class ScoreJudge(Node):
    def __init__(self):
        super().__init__('score_judge')
        self.pos = None
        self.sub_pos = self.create_subscription(String, '/robot_pos', self.on_pos, 10)
        self.sub_end = self.create_subscription(String, '/end_shot', self.on_end, 10)
        self.pub_score = self.create_publisher(String, '/shot_score', 10)
        self.get_logger().info('score_judge 시작')

    def on_pos(self, msg):
        """천장폰 마커 검출: {"x":0.42,"y":0.55} (연속 5Hz)"""
        self.pos = json.loads(msg.data)

    def on_end(self, msg):
        """심판(웹)의 샷 종료 선언 → 최종 위치로 점수 확정 (엣지)"""
        if self.pos is None:
            return
        d = math.hypot(self.pos['x'] - TARGET[0], self.pos['y'] - TARGET[1])
        score = 0
        for r, s in RINGS:
            if d <= r:
                score = s
                break
        out = String()
        out.data = json.dumps({'team': msg.data, 'dist': round(d, 3),
                               'score': score})
        self.pub_score.publish(out)
        self.get_logger().info(f'{msg.data}: d={d:.3f} → {score}점')


def main():
    rclpy.init()
    node = ScoreJudge()
    try:
        rclpy.spin(node)
    except KeyboardInterrupt:
        pass
    finally:
        node.destroy_node()
        rclpy.shutdown()


if __name__ == '__main__':
    main()
```

### 4.3 🤖 drive_node / 🌐 대시보드 / 🔩 경기장

- **drive_node**: A2 safety_supervisor에서 detection 로직만 뺀 축약판
  (조이스틱 + 0.5초 타임아웃). 재사용을 명시하고 출처를 주석에 남기세요.
- **대시보드**: 팀 등록 → 대진표(S2) → 라운드 진행(타이머 시작/샷 종료
  선언 버튼) → `/shot_score` 수신해 점수판 갱신. `/end_shot`은 사람이
  누르는 것이 기본(로봇 정지 자동 판정은 C 수준).
- **경기장**: 2m×2m, 하우스 3링(테이프). **정규화 링 반경과 실제 cm의
  대응**을 규격 도면에 명시 — RINGS 값의 근거가 됩니다.

> ⚠️ **스타터 코드의 알려진 한계(조가 해결할 것)**
> ① 판정이 `/end_shot` 순간의 단일 좌표 1개에 의존합니다 — 마커가 그
> 순간 미검출이면 판정 불가, 노이즈면 오판입니다. **최근 1초 좌표
> 중앙값**으로 판정하도록 개선하세요(측정 시스템 설계의 핵심 교훈).
> ② TARGET·RINGS가 하드코딩입니다 — 대시보드에서 캘리브레이션(표적
> 클릭)으로 설정하는 구조가 S 수준 개선입니다. ③ 마커 이탈(경기장 밖)
> 상황의 실격 판정이 없습니다 — RULES.md에 규정을 만들고 구현하세요.
