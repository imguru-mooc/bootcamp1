## 1. 프로젝트 개요

### 1.1 시나리오

교실 벽에 전시물(그림·사진) 3~5점을 걸고 각 전시물 옆에 QR을 붙입니다.
도슨트 로봇은 관람 코스를 따라 이동하다 전시물 QR을 인식하면 정지하고,
로봇 거치 폰의 **TTS(Web Speech Synthesis)**로 한국어 해설을 재생합니다.
해설이 끝나면 얼굴 감지로 관람객이 따라왔는지 확인한 뒤 다음 전시물로
이동하며, 관리 웹앱에서는 관람 코스 편집(순서·해설문)과 진행 현황을
관리합니다.

💡 해설 콘텐츠(전시물 선정·해설문 작성·녹음 톤 튜닝)가 정식 산출물이라
비개발 성향 조원의 기여 지점이 분명한 주제입니다.

### 1.2 학습 목표

1. 이동→인식→재생→확인의 다단계 투어 상태머신(MOVE→EXPLAIN→CHECK)을 설계할 수 있다.
2. 웹 TTS 재생 완료(비동기 이벤트)를 ROS 흐름에 연결할 수 있다.
3. 코스 데이터(순서+콘텐츠)를 웹에서 편집해 로봇에 주입하는 구조를 만들 수 있다.
4. 사용자(관람객) 부재 상황의 대기·타임아웃 정책을 설계할 수 있다.

### 1.3 시스템 구조

```
〔관리자 폰/PC〕 코스 편집 + 진행 현황 웹앱
   │ /course (JSON, 엣지)            ▲ /tour_state (엣지)
   ▼                                 │
  wss ──── rosbridge_server ─────────┘
   │
   ▼
〔Pi〕 docent_node (MOVE→EXPLAIN→CHECK) ──/cmd_vel(연속)──▶ 터틀봇
   ▲ /exhibit_seen  ▲ /tts_done  ▲ /audience        │ /tts_text (엣지)
   │                │            │                   ▼
〔로봇 거치 폰〕 QR 인식 + TTS 재생 + 얼굴 감지 (한 페이지)
```

### 1.4 조원 역할 (5~6인)

| 역할 | 담당 | 핵심 산출물 |
|---|---|---|
| 🌐 웹 | 코스 편집기 + 진행 현황 | admin.html |
| 🧠 AI | QR 인식 + 얼굴 감지 + TTS 통합 페이지 | robot.html |

## 3. 토픽 인터페이스 정의서 (INTERFACE.md 초안)

| 토픽명 | 메시지 타입 | 발행자 | 구독자 | 주기 | 성격 | QoS |
|---|---|---|---|---|---|---|
| /course | std_msgs/msg/String (JSON) | 관리 웹앱 | docent_node | 편집 적용 시 | 엣지 | RELIABLE |
| /exhibit_seen | std_msgs/msg/String (전시물ID) | 로봇 폰 | docent_node | 인식 시 | 엣지 | RELIABLE |
| /tts_text | std_msgs/msg/String | docent_node | 로봇 폰(TTS) | 해설 시작 시 | 엣지 | RELIABLE |
| /tts_done | std_msgs/msg/Bool | 로봇 폰 | docent_node | 재생 완료 시 | 엣지 | RELIABLE |
| /audience | std_msgs/msg/Bool | 로봇 폰 | docent_node | 상태 변화 시 | 엣지 | RELIABLE |
| /tour_state | std_msgs/msg/String (JSON) | docent_node | 관리 웹앱 | 변화 시 | 엣지 | RELIABLE |
| /cmd_vel | geometry_msgs/msg/Twist | docent_node | 터틀봇 | 10Hz | **연속** | RELIABLE |

**코스 JSON**: `[{"id":"E1","title":"별이 빛나는 밤","script":"이 작품은..."}, ...]`

> ⚠️ `/tts_text` → (재생) → `/tts_done`은 A5의 lift_cmd↔lift_done과 같은
> **요청-완료 페어**입니다. TTS 재생 시간은 해설 길이에 따라 다르므로
> 고정 대기(sleep)가 아니라 완료 이벤트로 흐름을 잇는 것이 핵심입니다.

## 4. 구현 가이드

### 4.1 🧠 로봇 폰 통합 페이지 (robot.html)

QR 인식(BarcodeDetector, A4 패턴) + 얼굴 감지(A1 패턴) + TTS를 한
페이지에서 운용합니다.

```javascript
// TTS: /tts_text 구독 → 재생 → 완료 시 /tts_done 발행
ttsTopic.subscribe((msg) => {
  const u = new SpeechSynthesisUtterance(msg.data);
  u.lang = 'ko-KR';
  u.rate = 0.95;                       // 도슨트 톤 (S2에서 튜닝)
  u.onend = () => ttsDone.publish(new ROSLIB.Message({ data: true }));
  speechSynthesis.speak(u);
});
```

💡 모바일 브라우저는 **사용자 제스처 이후에만** 음성 재생을 허용합니다.
페이지에 "투어 준비" 버튼을 만들어 최초 1회 터치로 TTS를 활성화하세요
(이걸 모르면 Day 4에 "폰에서만 소리가 안 나요"로 반나절을 씁니다).

### 4.2 📝 해설 대본 (콘텐츠 담당)

전시물당 20~40초 분량(250~450자). TTS로 재생해 보며 어색한 조사·숫자
읽기를 다듬은 **튜닝 전/후 비교 기록**을 남기세요 — S2 산출물이자
발표에서 재미있는 소재가 됩니다.

### 4.3 🤖 docent_node.py (py_compile 검증 완료)

```python
#!/usr/bin/env python3
"""docent_node: 코스 순회 → QR 전시물 정지 → 해설 → 관람객 확인 후 이동"""
import json, time
import rclpy
from rclpy.node import Node
from std_msgs.msg import String, Bool
from geometry_msgs.msg import Twist

CRUISE = 0.08
WAIT_AUDIENCE = 20.0   # 관람객 미확인 최대 대기 (초)


class DocentNode(Node):
    def __init__(self):
        super().__init__('docent_node')
        self.sub_course = self.create_subscription(String, '/course', self.on_course, 10)
        self.sub_qr = self.create_subscription(String, '/exhibit_seen', self.on_qr, 10)
        self.sub_tts = self.create_subscription(Bool, '/tts_done', self.on_tts_done, 10)
        self.sub_face = self.create_subscription(Bool, '/audience', self.on_audience, 10)
        self.pub_vel = self.create_publisher(Twist, '/cmd_vel', 10)
        self.pub_tts = self.create_publisher(String, '/tts_text', 10)
        self.pub_state = self.create_publisher(String, '/tour_state', 10)
        self.course = []          # [{'id':'E1','script':'...'}, ...]
        self.idx = 0
        self.phase = 'IDLE'       # IDLE→MOVE→EXPLAIN→CHECK
        self.audience = False
        self.check_since = 0.0
        self.timer = self.create_timer(0.1, self.tick)
        self.get_logger().info('docent_node 시작')

    def broadcast(self):
        msg = String()
        msg.data = json.dumps({'phase': self.phase, 'idx': self.idx,
                               'total': len(self.course)}, ensure_ascii=False)
        self.pub_state.publish(msg)

    def on_course(self, msg):
        """웹 코스 편집기: 전시물 순서+해설 스크립트"""
        self.course = json.loads(msg.data)
        self.idx = 0
        self.phase = 'MOVE'
        self.broadcast()

    def on_qr(self, msg):
        if self.phase == 'MOVE' and self.course and \
           msg.data == self.course[self.idx]['id']:
            self.phase = 'EXPLAIN'
            tts = String()
            tts.data = self.course[self.idx]['script']
            self.pub_tts.publish(tts)       # 웹 TTS가 재생 (엣지)
            self.broadcast()

    def on_tts_done(self, msg):
        if self.phase == 'EXPLAIN' and msg.data:
            self.phase = 'CHECK'            # 관람객 확인 단계
            self.check_since = time.time()
            self.broadcast()

    def on_audience(self, msg):
        self.audience = bool(msg.data)

    def tick(self):
        cmd = Twist()
        if self.phase == 'MOVE':
            cmd.linear.x = CRUISE
        elif self.phase == 'CHECK':
            waited = time.time() - self.check_since
            if self.audience or waited > WAIT_AUDIENCE:
                self.idx += 1
                self.phase = 'MOVE' if self.idx < len(self.course) else 'IDLE'
                self.broadcast()
        self.pub_vel.publish(cmd)           # 10Hz 연속


def main():
    rclpy.init()
    node = DocentNode()
    try:
        rclpy.spin(node)
    except KeyboardInterrupt:
        pass
    finally:
        node.destroy_node()
        rclpy.shutdown()


if __name__ == '__main__':
    main()
```

> ⚠️ **스타터 코드의 알려진 한계(조가 해결할 것)**
> ① 코스가 순서를 강제하므로 로봇이 다음 전시물 QR을 지나쳐도 계속
> 전진합니다(A5와 같은 미인식 문제) — **미인식 타임아웃**을 넣으세요.
> ② 투어 중 `/course` 재수신 시 즉시 처음으로 리셋됩니다 — 투어 중
> 편집 반영 정책(즉시/다음 투어부터)을 조가 결정하세요. ③ CHECK에서
> 관람객이 있으면 통과하는데, "해설 중 관람객이 떠나면?"은 미처리 —
> C 수준 개선 여지입니다. ④ 곡선 코스면 MOVE가 직진뿐이라 부족합니다 —
> 전시물 간 구간별 시퀀스(A1 ROUTES 패턴)로 확장하세요.

## 7. 트러블슈팅

| 증상 | 원인 | 해결 |
|---|---|---|
| 폰에서 TTS 무음 | 사용자 제스처 없이 재생 시도 | "투어 준비" 버튼 최초 1회 터치 (§4.1 💡) |
| tts_done이 안 옴 | onend 미등록/speak 중단 | utterance 이벤트 확인, 긴 해설은 분할 |
| QR을 지나쳐 계속 전진 | 알려진 한계 ① | 미인식 타임아웃 구현 |
| 다음 전시물 QR을 먼저 인식 | 코스 순서와 물리 배치 불일치 | 도면과 course 순서 대조 |
| 해설이 중간에 끊김 | 페이지 백그라운드 전환 | 화면 꺼짐 방지(Wake Lock) 또는 밝기 유지 |
| 얼굴 확인이 항상 실패 | 카메라가 전시물 방향 | 폰 거치 각도(관람객 방향) 조정 |
| 편집이 로봇에 반영 안 됨 | /course 발행 시점 | "적용" 버튼에서 명시 발행, echo 확인 |
| 곡선 코스에서 이탈 | MOVE 직진뿐 (한계 ④) | 구간 시퀀스 확장 |
