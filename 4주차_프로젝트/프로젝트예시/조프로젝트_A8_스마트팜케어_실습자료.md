## 1. 프로젝트 개요

### 1.1 시나리오

로봇이 화분 3개를 정해진 경로로 순회합니다. 각 화분 앞에 정지하면 거치
폰의 **직접 학습시킨 이미지 분류 모델**(Teachable Machine)이 잎 상태
(정상/시듦/과습)를 판정하고, 토양 수분 센서값과 함께 관리 대시보드의
화분별 카드에 기록됩니다. "시듦 + 토양 건조" 판정이면 서보 급수
밸브가 2초간 열립니다.

이 주제의 차별점: 사전학습 모델이 아니라 **조가 직접 촬영·라벨링한
데이터셋으로 모델을 만드는** 경험이 포함됩니다.

### 1.2 학습 목표

1. 데이터 수집 → 라벨링 → 학습 → 배포(웹) 파이프라인을 직접 수행할 수 있다.
2. 분류 신뢰도(confidence) 임계 설계와 오분류 대응을 경험할 수 있다.
3. AI 판정 + 센서값의 **AND 조건 의사결정**(급수)을 구현할 수 있다.
4. 순회-정지-측정-기록의 라운드 로빈 작업 패턴을 구현할 수 있다.

### 1.3 시스템 구조

```
〔관리자 폰/PC〕 화분 카드 대시보드
     ▲ /farm_state (엣지)
     │
    wss ──── rosbridge_server
     │
     ▼
〔Pi〕 farm_patrol ──/cmd_vel(연속)──▶ 터틀봇 (화분 순회, 정지 시 /at_pot 발행)
        plant_logger ◀─/plant_status(엣지)─ 〔로봇 거치 폰〕 분류 웹앱(Teachable Machine)
             ▲  └──/valve(엣지)──▶ valve_node(서보 급수)
             │ /soil (엣지)
        soil_sensor(ADS7830 토양 수분, 화분 정지 시 측정)
```

### 4.1 🧠 데이터셋 구축 (AI A) — 이 주제의 심장

- 클래스: 정상 / 시듦(잎 처짐) / 과습(잎 황변·처짐) — 실물 화분이

- 배경·조명 다양화, 학습/검증 8:2 분리. 구축 과정(촬영 조건표, 클래스
  정의 기준 사진)을 기록해 보고서에 — 이것이 S 수준 가점의 핵심 근거.

### 4.3 🤖 farm_patrol / plant_logger

**farm_patrol**: A1 `table_driver`의 시퀀스 패턴을 재사용해 화분 1→2→3→홈
순회, 각 화분 앞 정지 시 `/at_pot` 발행 후 15초 대기(판정·측정 시간)
뒤 다음 화분으로. 대기 중에도 `/cmd_vel` 0,0을 10Hz 발행(워치독).

**plant_logger.py (py_compile 검증 완료)**

```python
#!/usr/bin/env python3
"""plant_logger: 화분별 관리 카드 유지 + 급수 판단"""
import json, time
import rclpy
from rclpy.node import Node
from std_msgs.msg import String

SOIL_DRY = 80          # ADC값 기준 건조 임계 (실측 보정)
CONF_MIN = 0.7         # 분류 신뢰도 임계


class PlantLogger(Node):
    def __init__(self):
        super().__init__('plant_logger')
        self.cards = {}    # pot_id → {'label':..., 'conf':..., 'soil':..., 'ts':...}
        self.sub_status = self.create_subscription(
            String, '/plant_status', self.on_status, 10)
        self.sub_soil = self.create_subscription(String, '/soil', self.on_soil, 10)
        self.pub_state = self.create_publisher(String, '/farm_state', 10)
        self.pub_valve = self.create_publisher(String, '/valve', 10)
        self.get_logger().info('plant_logger 시작')

    def on_status(self, msg):
        """웹 분류 결과: {"pot":1,"label":"시듦","conf":0.85} (엣지)"""
        d = json.loads(msg.data)
        if d.get('conf', 0) < CONF_MIN:
            return                              # 신뢰도 미달은 무시
        card = self.cards.setdefault(d['pot'], {})
        card.update(label=d['label'], conf=d['conf'], ts=time.time())
        self.decide(d['pot'])
        self.broadcast()

    def on_soil(self, msg):
        """{"pot":1,"value":65} (순회 중 측정, 엣지)"""
        d = json.loads(msg.data)
        card = self.cards.setdefault(d['pot'], {})
        card.update(soil=d['value'], ts=time.time())
        self.decide(d['pot'])
        self.broadcast()

    def decide(self, pot):
        """시듦 판정 + 토양 건조 → 급수 (엣지 1회)"""
        c = self.cards[pot]
        if c.get('label') == '시듦' and c.get('soil', 999) < SOIL_DRY:
            if not c.get('watered'):
                c['watered'] = True
                msg = String()
                msg.data = json.dumps({'pot': pot, 'sec': 2.0})
                self.pub_valve.publish(msg)
                self.get_logger().info(f'화분 {pot} 급수')

    def broadcast(self):
        msg = String()
        msg.data = json.dumps(self.cards, ensure_ascii=False)
        self.pub_state.publish(msg)


def main():
    rclpy.init()
    node = PlantLogger()
    try:
        rclpy.spin(node)
    except KeyboardInterrupt:
        pass
    finally:
        node.destroy_node()
        rclpy.shutdown()


if __name__ == '__main__':
    main()
```

### 4.4 🔩 토양 수분 센서 / 서보 밸브

- soil_sensor: ADS7830(공식 `0x84 | (((chn<<2|chn>>1)&0x07)<<4)`)으로
  수분 센서 읽기. `/at_pot` 수신 시 해당 화분 채널 측정 → `/soil` 발행.
  건조/습윤 실측 캘리브레이션 표(마른 흙·젖은 흙 각 10회)가 SOIL_DRY의 근거.
- valve_node: A4 gate_node 패턴 재사용(각도 개방 → sec 후 폐쇄).
  실제 물 대신 **밸브 동작만** 시연해도 됩니다(전자 안전 우선). 물을 쓸
  경우 배선과 완전 분리하세요.

> ⚠️ **스타터 코드의 알려진 한계(조가 해결할 것)**
> ① `watered` 플래그가 영구적이라 한 번 급수한 화분은 **다시는 급수되지
> 않습니다** — S2(다음 순회까지 잠금 후 해제) 또는 시간 기반 리셋을
> 설계하세요. ② 세 화분이 채널·번호로만 구분되므로 화분↔채널↔순회 순서
> 매핑표를 INTERFACE.md에 반드시 명시하세요(통합 단계 단골 사고 지점).
