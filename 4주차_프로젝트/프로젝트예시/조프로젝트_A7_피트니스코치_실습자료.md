## 1. 프로젝트 개요

### 1.1 시나리오

사용자가 로봇 앞에서 스쿼트를 하면 로봇 거치 폰의 Pose Landmarker가
무릎 각도로 자세를 판정해 횟수를 셉니다. 로봇은 사용자와 일정 거리를
유지하도록 스스로 전후진하고, LCD에 횟수를 표시하며 부저로 운동
페이스를 알려줍니다. 세트 종료 후 사용자 폰의 웹앱에는 세트별 횟수와
자세 점수 리포트가 표시됩니다.

### 1.2 학습 목표

1. 관절 랜드마크로부터 각도를 계산하고 운동 1회를 판정하는 **반복 카운팅 상태머신**을 만들 수 있다.
2. 인물 크기(바운딩 높이)를 피드백으로 하는 **P 제어 거리 유지**를 구현할 수 있다.
3. 데드밴드·이득 튜닝이 제어 안정성에 미치는 영향을 실험으로 확인할 수 있다.
4. 운동 데이터(연속)와 카운트 이벤트(엣지)를 리포트로 집계할 수 있다.

### 1.3 시스템 구조

```
〔로봇 거치 폰〕 Pose Landmarker 웹앱
   ├ /person_size (Float32, 연속 10Hz)  ── 거리 유지 피드백
   ├ /rep_count (Int32, 엣지)           ── 1회 완료 시
   ├ /pose_score (Float32, 엣지)        ── 1회당 자세 점수
   └ /set_active (Bool, 엣지)           ── 세트 시작/종료
        │
       wss ──── rosbridge_server ────▶ 〔사용자 폰〕 리포트 웹앱 (구독)
        │
        ▼
〔Pi〕 coach_node ──/cmd_vel(연속)──▶ 터틀봇 (거리 유지)
        └─ /lcd_text, /buzzer (엣지) ──▶ LCD(REP 표시)·부저(페이스)
```

## 4. 구현 가이드

### 4.1 🧠 무릎 각도와 반복 카운팅 (AI A)

무릎 각도 = 엉덩이(24)-무릎(26)-발목(28) 세 점의 사잇각.

```javascript
function angle(a, b, c) {   // b를 꼭짓점으로 하는 각도
  const v1 = [a.x - b.x, a.y - b.y], v2 = [c.x - b.x, c.y - b.y];
  const cos = (v1[0]*v2[0] + v1[1]*v2[1]) /
              (Math.hypot(...v1) * Math.hypot(...v2));
  return Math.acos(cos) * 180 / Math.PI;
}
// 카운팅 상태머신: STAND(>150°) → DOWN(<100°) → STAND 복귀 시 +1
if (phase === 'STAND' && knee < 100) phase = 'DOWN';
else if (phase === 'DOWN' && knee > 150) { phase = 'STAND'; publishRep(++rep); }
```

💡 히스테리시스(100°/150° 이중 임계)가 각도 흔들림에 의한 이중
카운트를 막습니다. 임계값 결정 근거(판정 기준표)를 보고서에 넣으세요.

### 4.2 🧠 자세 점수와 person_size (AI B)

- 자세 점수(S1): 1회의 최저 무릎 각도가 90°에 가까울수록 + 상체 수직
  유지(어깨-엉덩이 기울기)에 가산 — 산식을 문서화하는 것 자체가 산출물.
- person_size: §3 ⚠️의 문제를 감안해 산출 기준(어깨 폭 |11−12| 등)을
  A와 함께 결정.

### 4.3 🤖 coach_node.py (py_compile 검증 완료)

```python
#!/usr/bin/env python3
"""coach_node: 거리 유지 + 횟수 카운트 표시 + 페이스 부저"""
import time
import rclpy
from rclpy.node import Node
from std_msgs.msg import String, Bool, Int32, Float32
from geometry_msgs.msg import Twist

TARGET_SIZE = 0.45     # 목표 인물 크기 (화면 높이 비율)
DEADBAND = 0.05
GAIN = 0.6             # P 제어 이득
SIZE_TIMEOUT = 1.0
PACE_SEC = 3.0         # 페이스 부저 주기 (운동 중)


class CoachNode(Node):
    def __init__(self):
        super().__init__('coach_node')
        self.sub_size = self.create_subscription(Float32, '/person_size', self.on_size, 10)
        self.sub_rep = self.create_subscription(Int32, '/rep_count', self.on_rep, 10)
        self.sub_set = self.create_subscription(Bool, '/set_active', self.on_set, 10)
        self.pub_vel = self.create_publisher(Twist, '/cmd_vel', 10)
        self.pub_lcd = self.create_publisher(String, '/lcd_text', 10)
        self.pub_buzzer = self.create_publisher(Bool, '/buzzer', 10)
        self.size = 0.0
        self.last_size = 0.0
        self.set_active = False
        self.last_pace = 0.0
        self.timer = self.create_timer(0.1, self.tick)
        self.get_logger().info('coach_node 시작')

    def on_size(self, msg):
        self.size = float(msg.data)
        self.last_size = time.time()

    def on_rep(self, msg):
        """웹 포즈 판정의 횟수 갱신 (엣지) → LCD 표시"""
        lcd = String()
        lcd.data = f'REP {msg.data}'
        self.pub_lcd.publish(lcd)

    def on_set(self, msg):
        self.set_active = bool(msg.data)

    def tick(self):
        cmd = Twist()
        person_alive = (time.time() - self.last_size) < SIZE_TIMEOUT
        if person_alive:
            err = self.size - TARGET_SIZE        # 크면 너무 가까움
            if abs(err) > DEADBAND:
                cmd.linear.x = float(-GAIN * err)  # P 제어: 가까우면 후진
        self.pub_vel.publish(cmd)                # 10Hz 연속
        # 페이스 부저 (운동 중에만, PACE_SEC 간격 엣지)
        if self.set_active and time.time() - self.last_pace > PACE_SEC:
            self.last_pace = time.time()
            buz = Bool()
            buz.data = True
            self.pub_buzzer.publish(buz)


def main():
    rclpy.init()
    node = CoachNode()
    try:
        rclpy.spin(node)
    except KeyboardInterrupt:
        pass
    finally:
        node.destroy_node()
        rclpy.shutdown()


if __name__ == '__main__':
    main()
```

> ⚠️ **스타터 코드의 알려진 한계(조가 해결할 것)**
> ① §3 ⚠️의 스쿼트-거리유지 간섭이 그대로 있습니다 — person_size 산출
> 기준 변경 또는 "세트 중 거리 유지 동결" 중 하나를 선택·구현하세요.
> ② 사용자가 좌우로 이동하면 화면에서 사라질 때까지 추종하지 못합니다 —
> C2(회전 추종)가 해법입니다. ③ P 제어 파라미터(GAIN·DEADBAND)는
> 미튜닝 상태입니다 — S2 실험표로 결정하세요(이득이 크면 로봇이
> 앞뒤로 진동하는 것을 직접 보게 됩니다. 그 영상 자체가 좋은 발표 자료입니다).
