## 1. 프로젝트 개요

### 1.1 시나리오

손을 쓸 수 없는 사용자를 가정합니다. 사용자는 **음성**으로 "전진"을
명령하고, 오작동 방지를 위해 **눈 2회 깜빡임**으로 확정해야 로봇이
출발합니다. 주행 중 조향은 **고개 방향**(좌우 회전)으로 하며, "정지"는
확정 없이 즉시 반영됩니다. LCD와 부저가 현재 입력 상태를 사용자에게
피드백합니다.

### 1.2 학습 목표

1. 세 가지 입력 모달리티(음성·표정·고개)를 하나의 중재 노드로 통합할 수 있다.
2. 위험 명령에 2단계 확정, 안전 명령(정지)에 즉시 반영이라는 **비대칭 안전 설계**를 할 수 있다.
3. 확정 대기 타임아웃이 있는 상태머신(IDLE→PENDING→ACTIVE)을 구현할 수 있다.
4. 모달리티별 오인식률을 측정·비교하는 실험을 설계할 수 있다.

### 1.3 시스템 구조

```
〔사용자 앞 거치 폰〕 멀티모달 입력 웹앱 (한 페이지)
   ├ Face Landmarker: 고개 yaw → /head_dir (Float32, 연속 10Hz)
   ├ Face blendshape: 눈 깜빡임 2회 → /confirm (Bool, 엣지)
   └ Web Speech STT: "전진"/"정지" → /voice_cmd (String, 엣지)
        │
       wss ──── rosbridge_server
        │
        ▼
〔Pi〕 input_arbiter (IDLE→PENDING→ACTIVE) ──/cmd_vel(연속)──▶ 터틀봇
        └─ /lcd_text, /buzzer (엣지) ──▶ LCD·부저 (상태 피드백)
```

## 4. 구현 가이드

### 4.1 🧠 고개 방향 (yaw) 추출

Face Landmarker의 얼굴 변환 행렬(facialTransformationMatrixes) 또는
좌우 랜드마크 대칭성으로 yaw를 추정해 −1~+1로 정규화합니다.

```javascript
// 간이 방식: 코(1) 기준 좌우 볼(234, 454)까지 거리 비율
const L = dist(lm[1], lm[234]), R = dist(lm[1], lm[454]);
const yaw = clamp((L - R) / (L + R) * 3.0, -1, 1);   // 캘리브레이션 계수
headTopic.publish(new ROSLIB.Message({ data: yaw }));  // 10Hz 연속
```

AI A의 실험: 실제 고개 각도(0/15/30°)와 yaw 출력의 대응표 → 조향 이득 결정 근거.

### 4.2 🧠 눈 2회 깜빡임 검출

blendshapes의 `eyeBlinkLeft`/`eyeBlinkRight` 평균이 임계(0.5) 초과 →
깜빡임 1회. **1.5초 시간창 안에 2회**면 의도적 확정으로 판정해 1회 발행.

```javascript
if (blink && !prevBlink) blinkTimes.push(now);
blinkTimes = blinkTimes.filter(t => now - t < 1500);
if (blinkTimes.length >= 2 && state === 'PENDING_UI') {
  blinkTimes = [];
  confirmTopic.publish(new ROSLIB.Message({ data: true }));
}
```

AI B의 실험: 자연 깜빡임 오인식률(1분 응시 중 오발행 횟수) vs 시간창
길이(1.0/1.5/2.0초) — 이 표가 S1의 핵심입니다.

### 4.3 🌐 음성 인식 (Web Speech API)

```javascript
const rec = new webkitSpeechRecognition();
rec.lang = 'ko-KR'; rec.continuous = true; rec.interimResults = false;
rec.onresult = (e) => {
  const text = e.results[e.results.length - 1][0].transcript.trim();
  if (text.includes('전진')) publish('/voice_cmd', '전진');
  if (text.includes('정지') || text.includes('멈춰')) publish('/voice_cmd', '정지');
};
```

💡 `continuous` 세션은 수십 초 후 자동 종료될 수 있으니 `onend`에서
재시작하세요. 인식 결과를 화면에 크게 표시해 사용자 피드백을 주는 것도
접근성 설계의 일부입니다.

### 4.4 🤖 input_arbiter.py (py_compile 검증 완료)

```python
#!/usr/bin/env python3
"""input_arbiter: 고개방향(연속) + 음성(엣지) + 깜빡임 확정(엣지) 2단계 안전 체계"""
import time
import rclpy
from rclpy.node import Node
from std_msgs.msg import String, Bool, Float32
from geometry_msgs.msg import Twist

CONFIRM_TIMEOUT = 5.0    # 확정 대기 제한 (초)
HEAD_TIMEOUT = 0.5       # 고개 입력 소실 → 정지
SPEED = 0.08


class InputArbiter(Node):
    def __init__(self):
        super().__init__('input_arbiter')
        self.sub_head = self.create_subscription(Float32, '/head_dir', self.on_head, 10)
        self.sub_voice = self.create_subscription(String, '/voice_cmd', self.on_voice, 10)
        self.sub_blink = self.create_subscription(Bool, '/confirm', self.on_blink, 10)
        self.pub_vel = self.create_publisher(Twist, '/cmd_vel', 10)
        self.pub_lcd = self.create_publisher(String, '/lcd_text', 10)
        self.pub_buzzer = self.create_publisher(Bool, '/buzzer', 10)
        self.state = 'IDLE'          # IDLE → PENDING → ACTIVE
        self.pending_cmd = None
        self.pending_since = 0.0
        self.head_yaw = 0.0          # -1(좌) ~ +1(우)
        self.last_head = 0.0
        self.timer = self.create_timer(0.1, self.tick)
        self.get_logger().info('input_arbiter 시작 (IDLE)')

    def lcd(self, text):
        msg = String()
        msg.data = text
        self.pub_lcd.publish(msg)    # 엣지

    def on_head(self, msg):
        self.head_yaw = float(msg.data)
        self.last_head = time.time()

    def on_voice(self, msg):
        word = msg.data.strip()
        if word == '정지':                       # 정지는 확정 불요 (즉시)
            self.state = 'IDLE'
            self.lcd('정지')
            return
        if self.state in ('IDLE', 'ACTIVE') and word == '전진':
            self.state = 'PENDING'
            self.pending_cmd = word
            self.pending_since = time.time()
            self.lcd('확인: 눈 2회 깜빡')

    def on_blink(self, msg):
        """깜빡임 2회 감지 시 웹이 True를 1회 발행 (엣지)"""
        if self.state == 'PENDING' and msg.data:
            self.state = 'ACTIVE'
            buz = Bool()
            buz.data = True
            self.pub_buzzer.publish(buz)
            self.lcd('주행 시작')

    def tick(self):
        # 확정 타임아웃
        if self.state == 'PENDING' and time.time() - self.pending_since > CONFIRM_TIMEOUT:
            self.state = 'IDLE'
            self.lcd('취소됨')
        cmd = Twist()
        head_alive = (time.time() - self.last_head) < HEAD_TIMEOUT
        if self.state == 'ACTIVE' and head_alive:
            cmd.linear.x = SPEED
            cmd.angular.z = -0.6 * self.head_yaw   # 고개 방향으로 조향
        self.pub_vel.publish(cmd)                  # 10Hz 연속


def main():
    rclpy.init()
    node = InputArbiter()
    try:
        rclpy.spin(node)
    except KeyboardInterrupt:
        pass
    finally:
        node.destroy_node()
        rclpy.shutdown()


if __name__ == '__main__':
    main()
```

> ⚠️ **스타터 코드의 알려진 한계(조가 해결할 것)**
> ① ACTIVE 중 "전진"을 다시 말하면 PENDING으로 빠지며 **주행이 멈춥니다** —
> 의도된 동작인지 조가 정책을 정하고 개선하세요. ② 얼굴 소실로 정지한 뒤
> 얼굴이 돌아오면 **확정 없이 재출발**합니다(ACTIVE 유지) — 소실 N초
> 이상이면 IDLE로 강등하는 안전 강화를 설계하세요. ③ '후진'(S3)은
> 미구현입니다. 이 프로젝트의 본질은 "어떤 입력을 얼마나 믿을 것인가"라는
> 안전 정책 설계입니다. 정책 결정과 근거를 보고서에 서술하세요.
