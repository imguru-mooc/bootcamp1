## 1. 프로젝트 개요

### 1.1 시나리오

사용자가 폰 화면에 손가락으로 도형(삼각형·별·하트)을 그리면, 웹앱이
궤적을 웨이포인트 배열로 변환해 로봇에 전송하고, 로봇은 **회전+직진
분해(데드레코닝)**로 바닥에서 그 궤적을 재현합니다. 웹앱은 목표 경로와
로봇이 보고하는 실제 주행 궤적(`/odom`)을 **겹쳐 그려** 오차를
시각화합니다. "명령한 대로 움직였는데 왜 어긋나는가" — 좌표 변환과
데드레코닝 누적 오차라는 로봇공학의 근본 문제를 체감하는 주제입니다.

### 1.2 학습 목표

1. 화면 좌표계 → 로봇 좌표계 변환(스케일·축 방향)을 구현할 수 있다.
2. 웨이포인트 열을 회전+직진 프리미티브로 분해할 수 있다 (atan2, 각도 정규화).
3. 오도메트리를 수신해 목표 대비 실주행 오차를 정량화할 수 있다.
4. 데드레코닝 오차의 원인(바퀴 미끄러짐·시간 양자화·보정 한계)을 실험으로 분석할 수 있다.

### 1.3 시스템 구조

```
〔사용자 폰〕 그림 웹앱 (Canvas)
   │ /waypoints (JSON, 엣지)          ▲ /progress (엣지)
   ▼                                  │        ▲ /odom (터틀봇 발행, 연속)
  wss ──── rosbridge_server ──────────┴────────┘
   │                                  (웹이 목표·실주행 겹쳐 그리기)
   ▼
〔Pi〕 path_executor ──/cmd_vel(10Hz 연속)──▶ 터틀봇
```

> 그림의 "위쪽"과 일치해야 오버레이가 맞습니다 — 시작 자세 규약을 정하세요.

## 4. 구현 가이드

### 4.1 🌐 그림 입력 + 단순화 (draw.html)

터치 궤적을 그대로 보내면 점이 수백 개라 실행이 불가능합니다.
최소 간격 필터(0.05 이상 이동 시만 채택)로 20점 이하로 단순화하세요.
(더 좋은 단순화 = Douglas-Peucker는 S 수준 가점)

```javascript
canvas.addEventListener('touchmove', (e) => {
  const p = norm(e.touches[0]);            // 0~1 정규화
  const last = pts[pts.length - 1];
  if (!last || Math.hypot(p.x - last.x, p.y - last.y) > 0.05)
    pts.push(p);
});
// 전송: y축 반전 규약 적용 (INTERFACE.md 결정에 따름)
wpTopic.publish(new ROSLIB.Message({
  data: JSON.stringify(pts.map(p => [p.x, 1 - p.y])) }));
```

### 4.2 🌐 궤적 비교 뷰 (/odom 오버레이)

```javascript
odomTopic.subscribe((msg) => {
```

최대 이탈 = 실주행 각 점에서 목표 경로까지 최근접 거리의 최댓값.

### 4.3 🤖 path_executor.py (py_compile 검증 완료)

```python
#!/usr/bin/env python3
"""path_executor: 웨이포인트 배열 → 회전+직진 분해 → 데드레코닝 재현"""
import json, math
import rclpy
from rclpy.node import Node
from std_msgs.msg import String
from geometry_msgs.msg import Twist

LIN_SPEED = 0.10       # m/s   (실측 보정: 1m 주행 시간 측정)
ANG_SPEED = 0.5        # rad/s (실측 보정: 360도 회전 시간 측정)
SCALE = 0.5            # 화면 정규화 1.0 → 실제 0.5 m


class PathExecutor(Node):
    def __init__(self):
        super().__init__('path_executor')
        self.sub_wp = self.create_subscription(String, '/waypoints', self.on_wp, 10)
        self.pub_vel = self.create_publisher(Twist, '/cmd_vel', 10)
        self.pub_prog = self.create_publisher(String, '/progress', 10)
        self.steps = []          # [('turn', rad), ('move', m)] → 시간으로 환산
        self.heading = 0.0       # 현재 방위 추정 (데드레코닝)
        self.timer = self.create_timer(0.1, self.tick)
        self.get_logger().info('path_executor 시작')

    def on_wp(self, msg):
        """[[x0,y0],[x1,y1],...] 정규화 좌표 (폰 그림)"""
        pts = json.loads(msg.data)
        self.steps = []
        self.heading = 0.0
        for i in range(1, len(pts)):
            dx = (pts[i][0] - pts[i-1][0]) * SCALE
            dy = (pts[i][1] - pts[i-1][1]) * SCALE
            target = math.atan2(dy, dx)
            dturn = self.norm(target - self.heading)
            self.heading = target
            dist = math.hypot(dx, dy)
            if abs(dturn) > 0.05:
                self.steps.append(['turn', dturn / ANG_SPEED,
                                   math.copysign(ANG_SPEED, dturn)])
            self.steps.append(['move', dist / LIN_SPEED, LIN_SPEED])
        # turn 시간은 부호 제거
        for s in self.steps:
            s[1] = abs(s[1])
        self.publish_progress(len(self.steps))
        self.get_logger().info(f'{len(pts)}점 → {len(self.steps)}스텝')

    @staticmethod
    def norm(a):
        while a > math.pi:
            a -= 2 * math.pi
        while a < -math.pi:
            a += 2 * math.pi
        return a

    def publish_progress(self, left):
        msg = String()
        msg.data = json.dumps({'steps_left': left})
        self.pub_prog.publish(msg)       # 엣지

    def tick(self):
        cmd = Twist()
        if self.steps:
            kind, remain, val = self.steps[0]
            if kind == 'turn':
                cmd.angular.z = float(val)
            else:
                cmd.linear.x = float(val)
            self.steps[0][1] = remain - 0.1
            if self.steps[0][1] <= 0:
                self.steps.pop(0)
                self.publish_progress(len(self.steps))
        self.pub_vel.publish(cmd)        # 10Hz 연속


def main():
    rclpy.init()
    node = PathExecutor()
    try:
        rclpy.spin(node)
    except KeyboardInterrupt:
        pass
    finally:
        node.destroy_node()
        rclpy.shutdown()


if __name__ == '__main__':
    main()
```

**M3 단위 테스트(필수)**: 로봇 없이 분해 로직만 검증하세요.
정사각형 `[[0,0],[1,0],[1,1],[0,1],[0,0]]` 입력 → turn이 +90°(1.571rad)
3회, move가 0.5m(SCALE 적용) 4회로 분해되는지 확인. 이 테스트를
TEST.md에 기록하는 것이 M3의 검증 방법입니다.

> ⚠️ **스타터 코드의 알려진 한계(조가 해결할 것)**
> ① 시간 양자화: 0.1초 tick이라 스텝마다 최대 0.1초의 과주행이 생기고
> **누적됩니다** — 잔여 시간을 다음 스텝에 이월하는 보정이 첫 개선 과제.
> ② LIN/ANG 명목값과 실제 속도의 차이가 스케일 오차를 만듭니다 —
> M6 캘리브레이션이 필수인 이유. ③ 데드레코닝 heading은 명령 기준
> 추정일 뿐 실제 방위가 아닙니다 — /odom과 비교해 어디서 벌어지는지
> 분석하는 것(S3)이 이 주제의 학술적 핵심입니다.
