## 1. 이 문서의 목적

5일 40시간 조 프로젝트에서 선택할 수 있는 주제 20개를 소개합니다.
모든 주제는 아래의 **공통 아키텍처**를 뼈대로 하며, 여기에 어떤 AI 모델과
어떤 하드웨어를 조합하느냐만 다릅니다. 조별로 이 중 하나를 선택하거나,
§5의 규정에 따라 자체 주제를 제안할 수 있습니다.

```
〔핸드폰〕 웹앱 (GitHub Pages, HTTPS)
   │  카메라·마이크·센서 → 브라우저 AI 추론 (온디바이스)
   │
   │  wss://<IP>:9090  (roslibjs)
   ▼
〔Pi/노트북〕 rosbridge_server (TLS WebSocket ↔ ROS 2)
   │
   ▼
〔로봇/HW〕 터틀봇 주행 + 서보·스테퍼·LCD·LED·부저·초음파·ADC 센서
```

### 모든 주제 공통 필수 요구사항

| # | 요구사항 | 비고 |
|---|---|---|
| 1 | 폰 웹앱 1개 이상 (GitHub Pages 배포) | 조작 화면 또는 대시보드 |
| 2 | AI/센서 입력 파이프라인 1개 이상 | 브라우저 추론 또는 폰 센서 |
| 3 | 액추에이터 2종 이상 제어 | 주행 + LCD/서보/부저 등 |
| 4 | 연속 명령 / 엣지 명령 구분 설계 | INTERFACE.md에 명시 |
| 5 | **안전장치 3종** | 입력 소실 정지, 백그라운드 정지, 워치독 연속 발행 |

> ⚠️ 어떤 주제를 골라도 안전장치 3종은 채점 대상(기능 5점 + 시연 영상 필수 장면)입니다.

## 3. 주제 상세 — A 시리즈 (서비스·시스템형)

### A1. 스마트 카페 서빙 로봇 ☕ 🟢

- **시나리오**: 손님이 테이블의 QR을 폰으로 찍어 주문 → 주방 대시보드에 주문 접수 → 로봇이 해당 테이블로 주행, LCD에 주문 내역 표시 + 부저로 도착 알림 → 얼굴 감지로 수령 확인 후 복귀
- **AI/입력**: BarcodeDetector(QR), Face Detector(수령 확인)
- **하드웨어**: 터틀봇 주행, LCD, 부저
- **대표 토픽**: `/order`(엣지) · `/cmd_vel`(연속) · `/lcd_text`(엣지) · `/buzzer`(엣지)
- **도전 요소**: 주문 큐 관리(FIFO), 테이블별 주행 시퀀스, 수령 타임아웃 처리
- **역할 포인트**: 주문 웹앱 / 주방 대시보드 / 주행 시퀀스 노드 / 통합

### A2. 재난 현장 정찰 로봇 🚨 🟡

- **시나리오**: 조종자는 현장이 보이지 않는 위치에서 FPV 영상만 보고 로봇을 원격 조종. 영상에서 사람이 탐지되면 자동 정지 + 이벤트 기록, 환경 센서값을 대시보드 그래프로 표시
- **AI/입력**: Object Detector(사람 탐지), DeviceOrientation(기울임 조종)
- **하드웨어**: 터틀봇 주행, 로봇 거치 폰(또는 web_video_server), ADC 센서(조도·온도)
- **대표 토픽**: `/cmd_vel`(연속) · `/detection`(엣지) · `/env_data`(1Hz 연속)
- **도전 요소**: 영상 지연 하에서의 조종성, 자동 정지 vs 수동 명령 우선순위
- **역할 포인트**: 조종 웹앱 / 탐지 파이프라인 / 센서·주행 노드 / 대시보드

### A3. 홈 시큐리티 순찰 로봇 🔒 🟡

- **시나리오**: 정해진 경로를 자율 순찰 → 사람 감지 시 사진 캡처 + 이벤트 타임라인 기록 + 보호자 폰 알림 → 보호자가 수동 조종 모드로 전환해 확인
- **AI/입력**: Face/Object Detector, 수동 모드용 가상 조이스틱
- **하드웨어**: 터틀봇 주행, LED(경광), 부저
- **대표 토픽**: `/patrol_state`(엣지) · `/cmd_vel`(연속) · `/event`(엣지)
- **도전 요소**: 자율↔수동 모드 전환 상태머신, 이벤트 스냅샷 저장·표시
- **역할 포인트**: 보호자 웹앱 / 감지 파이프라인 / 순찰 노드 / 모드 중재 노드

### A4. AI 스마트 주차 관리 시스템 🅿️ 🟢

- **시나리오**: 입구에서 차량(모형) QR 인식 → 서보 차단기 개방 → 주차면 초음파로 점유 감지 → 웹 대시보드에 실시간 주차 맵 + LED 유도등 → 만차 시 로봇이 빈 자리까지 선도 주행
- **AI/입력**: BarcodeDetector(QR)
- **하드웨어**: 서보(차단기), 초음파 ×N(주차면), LED, 터틀봇(선도)
- **대표 토픽**: `/gate`(엣지) · `/slot_status`(1Hz 연속) · `/cmd_vel`(연속)
- **도전 요소**: 다중 센서 토픽 집계, 대시보드 상태 동기화
- **역할 포인트**: 대시보드 / QR·입차 웹앱 / 센서 집계 노드 / 차단기·유도 노드

### A5. 창고 물류 AGV 시스템 📦 🟡

- **시나리오**: 웹앱에서 운송 작업(A→C) 등록 → 작업 큐 적재 → 로봇이 QR 스테이션을 인식하며 순서대로 처리 → 적재 지점에서 스테퍼 리프트 동작, LCD에 현재 작업 표시
- **AI/입력**: BarcodeDetector(스테이션 QR)
- **하드웨어**: 터틀봇 주행, 스테퍼(리프트), LCD
- **대표 토픽**: `/task_queue`(엣지) · `/cmd_vel`(연속) · `/stepper_steps`(엣지) · `/lcd_text`(엣지)
- **도전 요소**: 작업 스케줄링(FIFO vs 우선순위), 작업 상태 추적(대기/이동/완료)
- **역할 포인트**: 작업 등록 웹앱 / 스캐너 파이프라인 / 리프트·주행 노드 / 스케줄러 노드

### A6. 멀티모달 이동 보조 로봇 (접근성) ♿ 🔴

- **시나리오**: 손을 쓸 수 없는 사용자를 가정. 고개 방향(조향) + 음성 명령(동작) + 눈 깜빡임(확정)의 3중 입력. "전진" 음성 → 눈 2회 깜빡임 확인 후에만 출발하는 2단계 안전 체계
- **AI/입력**: Face Landmarker(고개·blendshape), Web Speech API(STT)
- **하드웨어**: 터틀봇 주행, LCD(입력 상태 표시), 부저(확인음)
- **대표 토픽**: `/head_dir`(연속) · `/voice_cmd`(엣지) · `/confirm`(엣지) · `/cmd_vel`(연속)
- **도전 요소**: 입력 모달리티별 오인식률 측정·비교, 확인 타임아웃 상태머신
- **역할 포인트**: 얼굴 파이프라인 / 음성 파이프라인 / 중재·주행 노드 / 실험·QA
- 💡 보고서에 모달리티별 인식률 실험표를 넣으면 문서 점수에 매우 유리합니다.

### A7. AI 피트니스 코치 로봇 💪 🟢

- **시나리오**: Pose Landmarker로 스쿼트·팔벌려뛰기 자세 판정 및 횟수 카운트 → 로봇이 사용자와 일정 거리 유지 → LCD 카운트 표시 + 부저 페이스 알림 → 운동 후 웹앱에 세트별 리포트
- **AI/입력**: Pose Landmarker(관절 각도)
- **하드웨어**: 터틀봇(거리 유지), LCD, 부저
- **대표 토픽**: `/rep_count`(엣지) · `/pose_score`(연속) · `/cmd_vel`(연속)
- **도전 요소**: 관절 각도 계산, 반복 동작 카운팅 상태머신(내려감→올라옴=1회)
- **역할 포인트**: 포즈 파이프라인 / 리포트 웹앱 / 거리 유지 노드 / LCD·부저 노드

### A8. 스마트팜 케어 로봇 🌱 🟢

- **시나리오**: 화분들을 순회하며 폰 카메라 + 커스텀 분류 모델로 식물 상태(정상/시듦/과습) 판정 → 토양수분 ADC값과 함께 화분별 관리 카드 기록 → 필요 시 서보 급수 밸브 동작
- **AI/입력**: Teachable Machine(직접 촬영·학습한 커스텀 모델)
- **하드웨어**: 터틀봇 순회, ADC(토양수분), 서보(급수)
- **대표 토픽**: `/plant_status`(엣지) · `/soil`(1Hz 연속) · `/valve`(엣지)
- **도전 요소**: 데이터셋 직접 구축(화분별 100장+), 분류 신뢰도 임계값 설계
- **역할 포인트**: 데이터셋·모델 / 관리 대시보드 / 순회·급수 노드 / 통합
- 💡 "내 데이터셋 → 내 모델 → 내 하드웨어" 전 과정을 경험하는 유일한 주제입니다.

### A9. 감정 인터랙션 반려로봇 🐾 🟡

- **시나리오**: 표정(웃음/찡그림/무표정)에 따라 로봇이 다가오기·물러나기·맴돌기로 반응, RGB LED와 LCD 이모지로 감정 표현. 손바닥 제스처(쓰다듬기)와 음성 호출에도 반응
- **AI/입력**: Face Landmarker blendshape, Hand Landmarker, Web Speech(호출어)
- **하드웨어**: 터틀봇 주행, RGB LED, LCD
- **대표 토픽**: `/emotion`(엣지) · `/cmd_vel`(연속) · `/led_color`(엣지)
- **도전 요소**: 행동 트리(behavior tree) 초급 설계 — 감정 상태별 행동 우선순위
- **역할 포인트**: 표정 파이프라인 / 제스처·음성 / 행동 트리 노드 / 표현 HW 노드

### A10. 협동 미로 탈출 — "Twitch Plays TurtleBot" 🎮 🔴

- **시나리오**: 관중 여러 명이 각자 폰으로 접속해 방향 투표 → 중재 노드가 1초 창(window) 다수결로 명령 확정 → 로봇이 미로 탈출. 투표 현황이 대시보드에 실시간 표시, 초음파 충돌 방지가 항상 우선
- **AI/입력**: 다중 클라이언트 투표(모델 불필요, 원하면 제스처 투표로 확장)
- **하드웨어**: 터틀봇 주행, 초음파(충돌 방지), LCD(현재 다수결)
- **대표 토픽**: `/vote`(다중 발행) · `/cmd_arbitrated`(1Hz 엣지) · `/cmd_vel`(연속)
- **도전 요소**: rosbridge 다중 클라이언트, 명령 중재(다수결·동점 처리), 안전 오버라이드 우선순위
- **역할 포인트**: 투표 웹앱 / 현황 대시보드 / 중재 노드 / 안전·주행 노드
- 💡 시연 때 다른 조 전원을 관중으로 참여시킬 수 있어 발표 효과가 가장 큽니다.

## 4. 주제 상세 — B 시리즈 (측정·교육·인터랙션형)

### B1. 미니 자율주행 도시 🚗 🟡

- **시나리오**: 라인 주행 중 폰 카메라 + 커스텀 모델로 교통표지판(정지/좌회전/속도제한) 인식 → 거동 변경. 별도의 인프라 노드가 LED 신호등으로 교차로 제어, 차량은 신호 토픽을 구독해 정지/통과
- **AI/입력**: Teachable Machine(표지판 분류)
- **하드웨어**: 터틀봇, LED(신호등), 적외선/카메라(라인)
- **대표 토픽**: `/sign`(엣지) · `/traffic_light`(엣지) · `/cmd_vel`(연속)
- **도전 요소**: 차량-인프라(V2I) 토픽 협상, 표지판 오인식 대비 신뢰도 임계값
- **역할 포인트**: 표지판 모델 / 관제 대시보드 / 차량 노드 / 인프라(신호등) 노드

### B2. 전시관 도슨트 로봇 🖼️ 🟢

- **시나리오**: 전시물 QR 인식 → 정지 → TTS로 한국어 해설 재생 → 얼굴 감지로 관람객 확인(없으면 대기) → 다음 전시물로 이동. 웹앱에서 관람 코스 편집·진행 현황 표시
- **AI/입력**: BarcodeDetector, Face Detector, Web Speech Synthesis(TTS)
- **하드웨어**: 터틀봇 주행, LCD(전시물 제목)
- **대표 토픽**: `/exhibit`(엣지) · `/tts_text`(엣지) · `/cmd_vel`(연속)
- **도전 요소**: 코스 편집 UI, 관람객 이탈 감지 후 재개 로직
- **역할 포인트**: 코스 편집 웹앱 / 인식·TTS / 주행 시퀀스 노드 / 해설 콘텐츠·QA
- 💡 해설 콘텐츠 제작이 있어 비개발 성향 조원의 기여 지점이 분명합니다.

### B3. 로봇 컬링 대회 플랫폼 🥌 🟡

- **시나리오**: 로봇을 조종해 표적 가까이 세우는 경기. 핵심은 **심판 자동화** — 천장 거치 폰이 색상 마커로 로봇 위치를 검출해 표적과의 거리로 점수 자동 판정. 대진표·점수판·경기 타이머(부저)를 웹으로 운영
- **AI/입력**: 색상 마커 검출(Canvas 픽셀 처리 또는 Object Detector)
- **하드웨어**: 터틀봇, 부저(타이머), 천장 거치 폰
- **대표 토픽**: `/robot_pos`(연속) · `/score`(엣지) · `/cmd_vel`(연속)
- **도전 요소**: 픽셀 좌표 → 실제 거리 캘리브레이션, 판정 재현성
- **역할 포인트**: 심판 비전 / 점수판·대진 웹앱 / 조종 웹앱 / 경기 운영 노드

### B4. 도서관 장서 점검 로봇 📚 🟢

- **시나리오**: 책등의 바코드/QR을 스캔하며 서가를 이동-정지-스캔 반복 → 재고 목록과 대조 → 오배열(등록 순서와 다른 책)을 찾아 대시보드에 보고
- **AI/입력**: BarcodeDetector
- **하드웨어**: 터틀봇(이동-정지 시퀀스), LCD(진행률)
- **대표 토픽**: `/scan_result`(엣지) · `/cmd_vel`(연속) · `/progress`(엣지)
- **도전 요소**: 스캔 데이터 정합성(중복·누락 처리), 이동-정지-스캔 시퀀스 타이밍
- **역할 포인트**: 스캔 파이프라인 / 재고 대시보드 / 시퀀스 노드 / 데이터 검증

### B5. 블록 코딩 로봇 교육 플랫폼 🧩 🟡

- **시나리오**: "초등학생용 제품" 가정. 웹앱의 블록 편집기로 시퀀스(앞으로 3초 → 좌회전 → 부저) 조립 → 로봇이 실행. 실행 중 초음파 장애물 감지 시 안전 중단. 최종일에 다른 조를 사용자로 UX 테스트
- **AI/입력**: 없음(원하면 시작 제스처 추가)
- **하드웨어**: 터틀봇, 초음파, 부저, LED
- **대표 토픽**: `/program`(엣지, JSON 시퀀스) · `/exec_state`(엣지) · `/cmd_vel`(연속)
- **도전 요소**: 시퀀스 인터프리터 노드(실행·일시정지·중단), 아동 친화 UI
- **역할 포인트**: 블록 편집기 / 인터프리터 노드 / HW·안전 노드 / UX 테스트 설계

### B6. 그림 그리는 경로 재현 로봇 ✏️ 🔴

- **시나리오**: 폰 화면에 손가락으로 그린 도형 → 웨이포인트 배열로 변환·전송 → 로봇이 오도메트리 기반으로 바닥에서 궤적 재현 → 웹앱이 목표 경로와 실제 궤적(/odom)을 겹쳐 그려 오차 시각화
- **AI/입력**: 터치 궤적 캡처(모델 불필요)
- **하드웨어**: 터틀봇(/odom 활용)
- **대표 토픽**: `/waypoints`(엣지) · `/odom`(구독) · `/cmd_vel`(연속)
- **도전 요소**: 좌표 변환(화면→월드), 웨이포인트 추종 제어, 데드레코닝 오차 분석
- **역할 포인트**: 드로잉 웹앱 / 궤적 비교 시각화 / 추종 제어 노드 / 오차 실험
- 💡 오차 원인 분석(바퀴 미끄러짐, 회전 누적 오차)을 보고서에 담기 좋은 주제입니다.

### B7. 수어 단어 통역 도우미 🤟 🔴

- **시나리오**: Hand Landmarker로 손 모양 **시퀀스**를 인식해 수어 단어 5~10개(안녕하세요, 감사합니다 등) 분류 → TTS 음성 + LCD 자막 출력 → 로봇이 인사 동작으로 응답
- **AI/입력**: Hand Landmarker + 시퀀스 매칭(슬라이딩 윈도우)
- **하드웨어**: LCD, 스피커(폰 TTS), 터틀봇(응답 동작)
- **대표 토픽**: `/sign_word`(엣지) · `/tts_text`(엣지) · `/cmd_vel`(연속)
- **도전 요소**: 정적 제스처가 아닌 **시간 축 동작 인식** — 프레임 시퀀스 정규화와 매칭
- **역할 포인트**: 시퀀스 인식 / 단어 사전·매칭 / 출력·동작 노드 / 인식률 실험
- > ⚠️ 반드시 5단어 축소 Plan B와 함께 설계 리뷰를 받으세요.

### B8. 시각장애인 보행 안내 로봇 🦯 🟡

- **시나리오**: 음성으로 목적지 지시 → 로봇이 앞장서 주행 → 초음파 장애물 거리를 **부저 간격**(가까울수록 빠르게)으로 전달. 사용자는 화면을 전혀 보지 않는다는 제약
- **AI/입력**: Web Speech(STT), 초음파
- **하드웨어**: 터틀봇, 초음파, 부저
- **대표 토픽**: `/voice_cmd`(엣지) · `/obstacle_dist`(연속) · `/cmd_vel`(연속)
- **도전 요소**: 비시각 인터페이스 설계(소리만으로 상태 전달), 거리→부저 간격 매핑 함수
- **역할 포인트**: 음성 파이프라인 / 소리 피드백 설계 / 주행·센서 노드 / 눈 가림 사용자 테스트

### B9. 실내 환경 히트맵 로봇 🌡️ 🟢

- **시나리오**: 교실을 격자 순회하며 지점마다 ADC로 조도·온도 측정 → 위치와 함께 기록 → 웹 대시보드에 색상 히트맵 렌더링. "에어컨 아래는 실제로 몇 도 낮은가"를 데이터로 답함
- **AI/입력**: 없음(측정 중심)
- **하드웨어**: 터틀봇(격자 순회), ADC(조도·온도)
- **대표 토픽**: `/measure`(엣지, 위치+값) · `/cmd_vel`(연속) · `/grid_state`(엣지)
- **도전 요소**: 측정-위치 동기화, Canvas 히트맵 렌더링, 격자 순회 시퀀스
- **역할 포인트**: 히트맵 대시보드 / 측정 노드 / 순회 노드 / 데이터 분석·보고서

### B10. AI 로봇 사진사 📸 🟡

- **시나리오**: 로봇 거치 폰이 얼굴·포즈 인식 → 인물이 3분할 구도점에 오도록 이동/팬틸트로 스스로 구도 조정 → TTS로 "왼쪽으로 한 걸음" 포즈 가이드 → 전원 웃는 표정에 자동 촬영 → 웹 갤러리 업로드
- **AI/입력**: Face Landmarker(표정), Pose Landmarker(구도)
- **하드웨어**: 터틀봇, 서보 팬틸트, 로봇 거치 폰
- **대표 토픽**: `/framing_error`(연속) · `/cmd_vel`(연속) · `/pan_tilt`(연속) · `/shutter`(엣지)
- **도전 요소**: 구도 오차 → 이동/팬틸트 배분(P 제어), 전원 웃음 판정(다인 처리)
- **역할 포인트**: 비전 파이프라인 / 갤러리 웹앱 / 구도 제어 노드 / 팬틸트·촬영 노드
