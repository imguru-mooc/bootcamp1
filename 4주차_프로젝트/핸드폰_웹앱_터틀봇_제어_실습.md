# 🖐 핸드폰 웹앱으로 터틀봇 제어하기
## — GitHub Pages + MediaPipe(브라우저 AI) + rosbridge(wss) —

---

## 1. 실습 개요

### 1.1 학습 목표

이번 실습을 마치면 다음을 할 수 있습니다.

1. rosbridge_server를 TLS(wss)로 실행하고, HTTPS 웹페이지에서 ROS 2 토픽을 발행할 수 있다.
2. GitHub Pages에 정적 웹앱을 배포하고 핸드폰 브라우저로 접속할 수 있다.
3. MediaPipe HandLandmarker(JavaScript)를 이용해 **브라우저 안에서(온디바이스)** 손가락 개수를 인식할 수 있다.
4. 디바운스와 워치독(연속 발행) 원칙을 웹 클라이언트에도 동일하게 적용할 수 있다.

### 1.2 준비물

| 구분 | 항목 | 비고 |
|---|---|---|
| 로봇 | 터틀봇 (또는 `/cmd_vel` 구독 로봇) | ROS 2 Humble, bringup 가능 상태 |
| SBC | Raspberry Pi 4B (Ubuntu 22.04) | rosbridge 실행용 (노트북도 가능) |
| 노트북 | GitHub 계정, git 사용 가능 | Pages 배포용 |
| 핸드폰 | 최신 Chrome 또는 Safari | 전면 카메라 사용 |
| 네트워크 | 공유기 1대 | **모든 기기가 같은 Wi-Fi/LAN** |

### 1.3 시스템 구조

```
〔핸드폰〕 github.io 웹앱 (HTTPS)
   │  전면 카메라 → MediaPipe(JS) 온디바이스 추론 → 손가락 개수
   │
   │  wss://<Pi IP>:9090  (roslibjs, JSON)
   ▼
〔Pi〕 rosbridge_server (TLS WebSocket ↔ ROS 2 토픽 변환)
   │
   │  /cmd_vel (geometry_msgs/msg/Twist)
   ▼
〔터틀봇〕 bringup 노드 → 모터 구동
```

💡 핸드폰은 ROS 노드가 아니라 rosbridge의 **웹소켓 클라이언트**입니다.
따라서 핸드폰에는 `ROS_DOMAIN_ID`나 DDS 설정이 전혀 필요 없습니다.

## 2. 왜 이렇게 구성하는가? (이론 배경)

### 2.1 HTTPS와 카메라 권한

브라우저의 카메라 API(`getUserMedia`)는 보안상 **HTTPS 페이지에서만** 동작합니다.
GitHub Pages(`https://<아이디>.github.io/...`)는 항상 HTTPS로 제공되므로,
인증서를 직접 발급하지 않아도 카메라 권한 문제가 자동으로 해결됩니다.

### 2.2 Mixed Content와 wss

HTTPS 페이지는 보안이 낮은 평문 연결(`ws://`)을 **차단**합니다(Mixed Content 정책).
따라서 rosbridge도 반드시 TLS가 적용된 `wss://`로 실행해야 합니다.
이때 사용하는 자체 서명 인증서는 브라우저가 신뢰하지 않으므로,
핸드폰에서 **한 번 수동으로 승인**하는 절차(STEP 4)가 필요합니다.

### 2.3 추론 위치: 온디바이스

MediaPipe Tasks for Web은 WASM/WebGL 기반으로 핸드폰 GPU에서 직접 실행됩니다.
영상은 네트워크로 전송되지 않고, **가벼운 제어 명령(JSON)만** 오가므로
지연이 작고 Wi-Fi 대역폭 부담이 거의 없습니다.

## 3. STEP 1 〔Pi〕 rosbridge를 wss로 실행하기

### 3.1 rosbridge 설치

```bash
$ sudo apt update
$ sudo apt install ros-humble-rosbridge-suite
```

### 3.2 자체 서명 인증서 생성

```bash
$ mkdir -p ~/certs && cd ~/certs
$ openssl req -x509 -newkey rsa:2048 -nodes \
    -keyout server.key -out server.crt -days 365 \
    -subj "/CN=$(hostname -I | awk '{print $1}')"
```

```bash
$ ls ~/certs
```
```
출력 ▶ (예시)
server.crt  server.key
```

💡 `CN`(Common Name)에는 Pi의 실제 IP가 들어갑니다.
IP가 바뀌는 환경이라면 공유기에서 Pi의 IP를 고정(DHCP 예약)해 두는 것을 권장합니다.

### 3.3 wss 모드로 실행

```bash
$ source /opt/ros/humble/setup.bash
$ ros2 launch rosbridge_server rosbridge_websocket_launch.xml \
    ssl:=true \
    certfile:=$HOME/certs/server.crt \
    keyfile:=$HOME/certs/server.key
```
```
출력 ▶ (예시)
[rosbridge_websocket-1] [INFO] [...]: Rosbridge WebSocket server started at wss://0.0.0.0:9090
```

> ⚠️ `ws://`(ssl 옵션 없이)로 실행하면 이후 github.io 페이지에서
> **절대 연결되지 않습니다.** Mixed Content 차단은 브라우저 콘솔에만 표시되고
> 화면상으로는 그냥 "연결 실패"로 보이므로 주의하세요.

### ✅ 체크포인트 1

- [ ] `ros2 launch ...` 출력에 `wss://0.0.0.0:9090` 문구가 보인다.
- [ ] `hostname -I`로 확인한 Pi의 IP를 메모했다. (예: `192.168.0.10`)

## 4. STEP 2 〔터틀봇〕 로봇 준비

터틀봇의 bringup을 실행하여 `/cmd_vel` 구독 상태로 만듭니다.

```bash
$ export TURTLEBOT3_MODEL=burger    # 모델에 맞게 (burger / waffle_pi)
$ ros2 launch turtlebot3_bringup robot.launch.py
```

로봇이 아직 준비되지 않았다면, 검증용으로 토픽 모니터만 띄워도 실습 진행이 가능합니다.

```bash
$ ros2 topic echo /cmd_vel
```

💡 rosbridge와 터틀봇이 서로 다른 기기라면 두 기기의 `ROS_DOMAIN_ID`가
같아야 합니다. (핸드폰은 무관 — 2.3절 참고)

### ✅ 체크포인트 2

- [ ] `ros2 topic list` 결과에 `/cmd_vel`이 보인다. (bringup 시)
- [ ] 또는 `ros2 topic echo /cmd_vel`이 대기 상태로 떠 있다.

## 5. STEP 3 〔노트북〕 GitHub Pages 배포

### 5.1 저장소 생성 및 업로드

1. GitHub에서 새 저장소 생성 — 이름 예시: `turtlebot-web` (Public)
2. 배포용 `index.html`(§7 전체 코드)을 저장소 **루트**에 업로드

git 명령으로 진행하는 경우:

```bash
$ git clone https://github.com/<아이디>/turtlebot-web.git
$ cd turtlebot-web
$ cp <다운로드 위치>/index.html .
$ git add index.html
$ git commit -m "터틀봇 제스처 제어 웹앱"
$ git push origin main
```

### 5.2 Pages 활성화

1. 저장소 → **Settings** → 좌측 메뉴 **Pages**
2. Source: `Deploy from a branch`
3. Branch: `main` / 폴더 `/ (root)` → **Save**
4. 1~2분 후 상단에 배포 주소가 표시됩니다.

```
출력 ▶ (예시)
Your site is live at https://<아이디>.github.io/turtlebot-web/
```

### ✅ 체크포인트 3

- [ ] 주소가 `https://`로 시작한다.

## 6. STEP 4 〔핸드폰〕 인증서 승인 — 가장 많이 막히는 단계!

핸드폰이 Pi와 **같은 Wi-Fi**에 연결된 상태에서 진행합니다.

1. 핸드폰 브라우저 주소창에 직접 입력: `https://<Pi IP>:9090`
   (예: `https://192.168.0.10:9090`)
2. "연결이 비공개로 설정되어 있지 않습니다" 경고 화면이 뜹니다.
3. **고급(Advanced)** → **안전하지 않음(계속 이동)** 을 눌러 승인합니다.
4. 빈 화면 또는 간단한 응답이 보이면 성공입니다.

💡 이 절차는 "이 자체 서명 인증서를 신뢰하겠다"는 예외 등록입니다.
이 승인이 있어야 이후 github.io 페이지에서 `wss://<Pi IP>:9090` 연결이 열립니다.

> ⚠️ 일부 iOS 버전/브라우저에서는 이 방식의 예외 승인이 wss에 적용되지 않을 수
> 있습니다. 이 경우 `mkcert`로 로컬 CA를 만들어 인증서를 발급하고,
> 루트 CA 파일을 핸드폰에 설치(iOS: 프로파일 설치 → 인증서 신뢰 활성화)하는
> 정공법을 사용합니다.

### ✅ 체크포인트 4

- [ ] `https://<Pi IP>:9090` 접속 시 인증서 경고를 승인했다.
- [ ] 승인 후 재접속하면 경고 없이 페이지가 열린다.

## 7. STEP 5 〔핸드폰〕 웹앱 접속 및 제어

### 7.1 접속 및 연결

1. 핸드폰 브라우저로 `https://<아이디>.github.io/turtlebot-web/` 접속
2. rosbridge 주소 입력란에 `wss://<Pi IP>:9090` 입력 → **연결하기**
3. 상태 표시가 초록색 "**rosbridge: 연결됨**"으로 바뀌는지 확인
4. 카메라 권한 요청이 뜨면 **허용**
5. 전면 카메라에 손을 비추고 손가락 개수를 바꿔가며 제어

### 7.2 제스처 매핑

| 손가락 개수 | 동작 | linear.x | angular.z |
|---|---|---|---|
| 0 (주먹) | 정지 | 0.0 | 0.0 |
| 1 | 전진 | +0.10 | 0.0 |
| 2 | 후진 | −0.10 | 0.0 |
| 3 | 좌회전 | 0.0 | +0.50 |
| 4 | 우회전 | 0.0 | −0.50 |
| 5 (보) | 정지 | 0.0 | 0.0 |

### 7.3 안전 동작 (자동 정지 3종)

| 상황 | 동작 |
|---|---|
| 손이 1초 이상 미검출 | 정지 명령 자동 발행 |
| 브라우저가 백그라운드로 전환 | 즉시 정지 발행 |
| "연결 해제" 버튼 | 정지 발행 후 연결 종료 |

### 7.4 검증

Pi(또는 노트북)에서 값이 실시간으로 바뀌는지 확인합니다.

```bash
$ ros2 topic echo /cmd_vel
```
```
출력 ▶ (예시) — 손가락 1개(전진)일 때
linear:
  x: 0.1
  y: 0.0
  z: 0.0
angular:
  x: 0.0
  y: 0.0
  z: 0.0
```

### ✅ 체크포인트 5

- [ ] 웹앱의 rosbridge 상태가 초록색 "연결됨"이다.
- [ ] 카메라 화면에 주황색 랜드마크 점 21개가 손을 따라다닌다.
- [ ] 손가락 개수를 바꾸면 `ros2 topic echo /cmd_vel` 값이 매핑표대로 바뀐다.
- [ ] 손을 화면 밖으로 치우면 1초 내에 0.0/0.0(정지)으로 돌아온다.

      messageType: "geometry_msgs/msg/Twist",
    });
    setDot("rosDot", "rosMsg", "ok", "rosbridge: 연결됨 (" + url + ")");
    $("btnConnect").style.display = "none";
    $("btnStop").style.display = "block";
  });
  ros.on("error", () => {
    setDot("rosDot", "rosMsg", "err",
      "rosbridge: 연결 실패 — 인증서 승인 여부와 IP를 확인하세요");
  });
  ros.on("close", () => {
    connected = false;
    setDot("rosDot", "rosMsg", "err", "rosbridge: 연결 끊김");
    $("btnConnect").style.display = "block";
    $("btnStop").style.display = "none";
  });
};

$("btnStop").onclick = () => {
  publishTwist(STOP);          // 마지막으로 정지 발행 후 해제
  committed = STOP;
  if (ros) ros.close();
};

function publishTwist(cmd) {
  if (!connected || !cmdVel) return;
  cmdVel.publish(new ROSLIB.Message({
    linear:  { x: cmd.lx, y: 0.0, z: 0.0 },
    angular: { x: 0.0, y: 0.0, z: cmd.az },
  }));
}

/* 연속 발행 루프: DC 구동계는 매 주기 명령 유지 (워치독 원칙) */
setInterval(() => {
  if (Date.now() - lastSeen > LOST_MS) committed = STOP;  // 손 소실 → 정지
  publishTwist(committed);
}, 1000 / PUB_HZ);

/* 화면 이탈(백그라운드) 시 즉시 정지 */
document.addEventListener("visibilitychange", () => {
  if (document.hidden) { committed = STOP; publishTwist(STOP); }
});

const video = $("video"), canvas = $("overlay");

  try {

/* 손가락 개수 세기: 검지~새끼는 tip.y < pip.y, 엄지는 x축 + 손 방향 */
function countFingers(lm, handedness) {
  let n = 0;
  const pairs = [[8, 6], [12, 10], [16, 14], [20, 18]];
  for (const [tip, pip] of pairs) if (lm[tip].y < lm[pip].y) n++;
  const right = handedness === "Right";     // 카메라 원본 기준
  if (right ? lm[4].x < lm[3].x : lm[4].x > lm[3].x) n++;
  return n;
}

function loop() {
  if (video.readyState >= 2) {
    const res = landmarker.detectForVideo(video, performance.now());
    ctx.clearRect(0, 0, canvas.width, canvas.height);

    if (res.landmarks && res.landmarks.length > 0) {
      lastSeen = Date.now();
      const lm = res.landmarks[0];
      const hand = res.handednesses?.[0]?.[0]?.categoryName ?? "Right";

      // 랜드마크 점 그리기
      ctx.fillStyle = "#E8590C";
      for (const p of lm) {
        ctx.beginPath();
        ctx.arc(p.x * canvas.width, p.y * canvas.height, 4, 0, Math.PI * 2);
        ctx.fill();
      }

      // 디바운스: STABLE_N 프레임 연속 동일 판정 시 확정
      const n = countFingers(lm, hand);
      if (n === candidate) {
        if (++stableFrames >= STABLE_N && CMD[n]) {
          committed = CMD[n];
          showCmd(n, committed);
        }
      } else {
        candidate = n;
        stableFrames = 1;
      }
    }
  }
  requestAnimationFrame(loop);
}

init();
</script>

## 9. 코드 핵심 해설

### 9.1 디바운스 — `STABLE_N = 8`

랜드마크 인식은 프레임마다 흔들릴 수 있습니다. 파이썬 캡스톤에서
12프레임 디바운스를 적용했던 것과 같은 원리로, **같은 판정이 8프레임 연속**될
때만 제스처를 확정(commit)합니다. 판정이 바뀌면 카운터를 1부터 다시 셉니다.

```javascript
if (n === candidate) {
  if (++stableFrames >= STABLE_N && CMD[n]) committed = CMD[n];
} else {
  candidate = n;
  stableFrames = 1;
}
```

### 9.2 연속 발행 — 워치독 원칙

DC 구동계 명령(`/cmd_vel`)은 **연속 명령**입니다. 제스처가 바뀔 때만 발행하면
로봇 쪽 워치독이 "명령 두절"로 판단할 수 있으므로, 확정된 명령을
`setInterval`로 **10Hz 연속 발행**합니다. 이는 캡스톤에서 세운
"DC 모터 = 매 프레임 연속 / 스테퍼·LCD = 변화 시에만" 원칙의 웹 버전입니다.

### 9.3 3중 안전장치

| 코드 | 역할 |
|---|---|
| `Date.now() - lastSeen > LOST_MS` | 손 미검출 1초 → 정지로 강제 전환 |
| `visibilitychange` 이벤트 | 앱 전환·화면 꺼짐 → 즉시 정지 발행 |
| 연결 해제 버튼 | 정지 발행 **후** `ros.close()` |

> ⚠️ 핸드폰은 노트북과 달리 백그라운드 전환이 매우 잦습니다.
> 원격 로봇 제어에서 이 3중 안전장치는 선택이 아니라 필수입니다.

### 9.4 손가락 카운트와 handedness

검지~새끼는 `tip.y < pip.y`(끝마디가 중간마디보다 위)로 판정하고,
엄지는 y축으로 판정할 수 없으므로 **x축 + 손 방향(handedness)** 을 씁니다.
오른손이면 엄지 끝(4번)이 마디(3번)보다 왼쪽에 있을 때 펴진 것으로 봅니다.
파이썬 MediaPipe에서 쓰던 것과 동일한 로직입니다.

### 9.5 메시지 타입 표기

ROS 2 rosbridge에서는 `geometry_msgs/msg/Twist`처럼 **`msg`가 포함된
전체 경로**를 사용합니다. ROS 1식 `geometry_msgs/Twist`와 혼동하지 마세요.

## 11. 트러블슈팅

| 증상 | 원인 | 해결 |
|---|---|---|
| "연결 실패"만 반복 | 인증서 미승인 | 핸드폰에서 `https://<IP>:9090` 접속 → 고급 → 계속 (STEP 4 재수행) |
| 승인했는데도 연결 실패 | `ws://`로 rosbridge 실행 | `ssl:=true certfile:=... keyfile:=...` 옵션 확인 |
| 카메라 권한 요청이 안 뜸 | HTTP 접속 또는 로컬 파일로 열람 | 반드시 `https://...github.io/...` 주소로 접속 |
| 연결됐는데 로봇이 안 움직임 | bringup 미실행 / 토픽명 불일치 | `ros2 topic list`, `ros2 topic echo /cmd_vel` 확인 |
| iOS에서만 wss 연결 안 됨 | 예외 승인 미적용 | mkcert 루트 CA를 폰에 설치 (프로파일 → 인증서 신뢰) |
| 모델 로딩이 오래 걸림 | 최초 1회 모델 다운로드(수 MB) | Wi-Fi 상태 확인 후 대기, 이후엔 캐시 사용 |
| 제스처 판정이 자주 튐 | 조명 부족 / 복잡한 배경 | 밝은 곳에서 단색 배경, `STABLE_N` 값을 12로 증가 |
| 제어 중 간헐적으로 멈춤 | 화면 자동 꺼짐 / 앱 전환 | 화면 켜짐 유지 설정, 백그라운드 전환 시 정지는 정상 동작 |
| Pi IP가 자꾸 바뀜 | DHCP 임대 갱신 | 공유기에서 Pi MAC 주소로 IP 고정(DHCP 예약) |
| 노트북에선 되는데 폰에서 안 됨 | 폰이 다른 네트워크(LTE/5G) | 폰의 Wi-Fi가 Pi와 같은 공유기인지 확인 |
